# Описание проекты

Классический порядок действительно выглядит примерно так: model/object space → view/camera space → clip space → clipping → perspective divide в NDC → viewport transform → rasterization → depth/color buffers. Важный нюанс: **clipping происходит до perspective divide**, а текстуры не «навешиваются» отдельной стадией — UV интерполируются при растеризации, а texture sampling выполняется при shading фрагмента. [cs.cmu](https://www.cs.cmu.edu/~fp/courses/02-graphics/pdf-2up/14-clip.pdf)

## Сначала уточни цель

Сформулируй себе MVP не как «рендерер сцены», а так:

> Программа берёт один треугольник с заданными вершинами, растеризует его в CPU framebuffer и сохраняет изображение.

Это может показаться слишком маленьким, но в нём уже есть центральная задача rasterization: определить, какие дискретные пиксели покрывает непрерывный треугольник. Barycentric coordinates затем позволят интерполировать цвет, глубину, UV и любые другие vertex attributes. [github](https://github.com/ssloy/tinyrenderer/wiki/Lesson-2:-Triangle-rasterization-and-back-face-culling)

На этом этапе всё должно быть **захардкожено**:

- Размер изображения, например \(512 \times 512\).
- Один треугольник в 2D screen coordinates.
- По цвету на вершину.
- Вывод в PPM — это проще, чем PNG и не отвлекает от CG.
- Без сцен, JSON, камер, матриц, текстур и классов `Mesh`.

Когда получишь правильный треугольник с плавным RGB-градиентом, у тебя уже будет основание всего проекта.

## Правильная декомпозиция

Твой начальный pipeline можно переосмыслить так:

```text
Scene / Mesh data
        ↓
Vertex processing:
object → world → view → clip
        ↓
Primitive assembly (triangles)
        ↓
Clipping in clip space
        ↓
Perspective divide: clip → NDC
        ↓
Viewport transform: NDC → screen
        ↓
Triangle rasterization
        ↓
Fragment processing:
interpolate attributes → shade/sample texture
        ↓
Depth test / blending
        ↓
Color framebuffer
```

В CMU растеризация формулируется как последовательность: преобразовать вершины в camera space, применить perspective projection, выполнить clipping, перейти к экранным координатам и независимо разрешить occlusion на каждом sample через depth buffer. [15462.courses.cs.cmu](http://15462.courses.cs.cmu.edu/spring2019content/lectures/08_rasterize/08_rasterize_slides.pdf)

Обрати внимание на два исправления к твоему списку:

- **Проекция и clipping**: ты проецируешь вершины в homogeneous clip space; потом клиппишь относительно view frustum; только после этого делишь координаты на \(w\).
- **Текстура и пиксели**: у треугольника есть UV в вершинах; при rasterization ты получаешь barycentric weights; затем интерполируешь UV и читаешь texel из изображения в fragment shader.

## План итераций

Сделай проект в форме последовательности вертикальных срезов. После каждого этапа делай изображение и сохраняй его в `examples/` или README.

| Итерация | Что появляется | Что ты должен увидеть |
|---:|---|---|
| 0 | Image + framebuffer | Одноцветная картинка |
| 1 | 2D point/line | Точки и линии в нужных координатах |
| 2 | 2D triangle coverage | Заполненный плоским цветом треугольник |
| 3 | Barycentric interpolation | Плавный градиент между тремя vertex colors |
| 4 | Bounding-box traversal и edge functions | Быстрая растеризация без прохода по всему экрану |
| 5 | 3D vertices + orthographic camera | Куб без перспективы |
| 6 | Model/View/Projection | Вращающийся в перспективе куб |
| 7 | Depth buffer | Несколько пересекающихся треугольников всегда рисуются корректно, независимо от порядка |
| 8 | Back-face culling | Не видны обратные стороны закрытого меша |
| 9 | Clipping | Треугольник корректно пересекает near plane, не «взрывается» |
| 10 | UV + texture sampling | Текстура правильно ложится на наклонённый quad |
| 11 | Perspective-correct UV | На наклонённой поверхности texture coordinates не «ползут» |
| 12 | Простой shading | Lambert или Blinn–Phong, визуализация нормалей |
| 13 | OBJ import | Модель вроде Suzanne/teapot с текстурой и камерой |

На первых четырёх итерациях ты уже изучишь больше, чем при пассивном просмотре нескольких лекций.

## С чего начать сегодня

Сделай подготовительную работу, но не пиши pipeline.

### Шаг 1. Зафиксируй рамки проекта

Ответь письменно на четыре вопроса:

1. Будет ли renderer offline?  
   Рекомендую: **да**. Программа рендерит изображение и сохраняет его на диск; окно и real-time не нужны.

2. Какая платформа?  
   C++17/20, CMake, Linux. Ты уже работаешь с C++ и Linux — не создавай себе новую проблему с окружением.

3. Какой первый формат вывода?  
   PPM. Он текстовый или бинарный, примитивный и хорошо подходит для первой картинки. PNG добавишь, когда framebuffer и pipeline уже работают.

4. Какой scope первой версии?  
   Один 2D-треугольник, vertex colors, изображение на диске. Ничего больше.

Сделай `README.md`, где в 8–12 строках запиши эту цель и список будущих этапов. Это станет твоим контрактом с самим собой против scope creep.

### Шаг 2. Нарисуй data flow

Не классы, а именно поток данных. Например:

```text
Triangle:
  positions: 3 × Vec2
  colors:    3 × Color

rasterize(triangle, framebuffer):
  для каждого pixel center:
    определить, покрыт ли он треугольником
    если да:
      вычислить barycentric weights
      смешать три цвета
      записать цвет
```

Сейчас намеренно не решай, *как именно* определять coverage и barycentrics. Вернись к лекции CMU по растеризации, попробуй вывести это самостоятельно через площади под-треугольников или oriented edge functions. Сравни оба подхода после своей первой попытки.

Практический совет: пиксель рассматривай как sample в его центре, то есть \((x+0.5, y+0.5)\). Это избавляет от части путаницы с границами.

### Шаг 3. Выбери первые инварианты

Прежде чем кодировать, придумай 3–5 проверок, которые обязаны выполняться:

- Поворот порядка вершин должен менять orientation, но не внутреннюю область треугольника.
- Сумма barycentric weights внутри треугольника должна быть равна 1 с допустимой погрешностью.
- В вершине соответствующий вес равен 1, а другие — 0.
- При одинаковом цвете всех трёх вершин весь треугольник имеет этот цвет.
- Если треугольник целиком за пределами framebuffer, буфер не меняется.

Это уже зачаток нормального test-driven мышления для графики.

## Про формат сцены

Твоя идея с конфигом правильная, но **преждевременная** для MVP. JSON-сцена добавит отдельные задачи:

- парсинг;
- обработку ошибок;
- система путей к ассетам;
- сереализация в C++ структуры;
- дизайн формата и его эволюция.

Всё это полезно, но пока не даст понимания rasterizer-а.

Рекомендую эволюцию:

1. **Hardcoded geometry** для 2D triangle.
2. Маленький текстовый формат или C++-описание нескольких triangles.
3. OBJ только для геометрии.
4. Собственный JSON для camera, lights, transforms, material parameters.
5. glTF, если проект станет real-time renderer или захочешь PBR-материалы и нормальный asset pipeline.

OBJ — хорошая следующая ступень, потому что геометрия там проста: позиции, нормали и UV; но он не обязан быть первым форматом.

## Главный вопрос, который нужно решить самому

Твоя первая настоящая задача:

> Как, имея вершины 2D-треугольника, для каждого pixel center эффективно определить: находится ли он внутри треугольника, и если да — какие barycentric weights соответствуют этой точке?

Не ищи пока готовый код. Посмотри лекцию CMU о rasterization, выпиши определение barycentric coordinates, затем реализуй решение на бумаге и проверь его на треугольнике с простыми координатами. Для растеризации распространённая стратегия — проходить только bounding box треугольника и проверять пиксели barycentric coordinates; отрицательный вес означает точку вне треугольника. [github](https://github.com/ssloy/tinyrenderer/wiki/Lesson-2:-Triangle-rasterization-and-back-face-culling)

Каждая из этих тем нужна, но первая победа должна быть маленькой: **записанная на диск картинка с правильно закрашенным 2D-треугольником**.

Когда она будет, следующим шагом можешь принести мне свои решения по двум вопросам: как ты определяешь принадлежность точки треугольнику и как представляешь framebuffer. Я помогу проверить рассуждение, не выдавая за тебя реализацию.
